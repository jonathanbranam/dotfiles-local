Move rcrc into this repo, one per machine under `host-<name>/rcrc`, and point the NUC's live $HOME links at bridle's clone. Write install docs for the first-run bootstrap. Depends on dl-b25b (host folders). Filed by advisor (notes) on 2026-10-03 from orchestrator note m-0009 and a discussion with the human.

## Background (from orchestrator, m-0009)
The NUC has two clones of dotfiles-local:
- `~/dotfiles-local`: what rcup links $HOME to. `~/.rcrc` is a symlink to thoughtbot's `~/dotfiles/rcrc`: `EXCLUDES="*.md LICENSE CODEOWNERS"`, `DOTFILES_DIRS="$HOME/dotfiles-local $HOME/dotfiles"`, `COPY_ALWAYS="git_template/HEAD"`. Has the tmux/plugins/tpm submodule initialized.
- `/srv/shared/work/dotfiles-work/dotfiles-local`: bridle's project clone. tpm submodule NOT initialized.
Changes made through bridle reach the live $HOME only when someone pulls into ~/dotfiles-local by hand. The human rejected making ~/dotfiles-local a symlink ("symlinks to symlinks aren't right"). Their plan: copy rcrc into dotfiles-local and point DOTFILES_DIRS at the right clone; the path is machine-specific (NUC: /srv/shared/work/dotfiles-work/dotfiles-local; Mac: likely $HOME/dotfiles-local; the work laptop uses a different repo).

## Design (agreed with the human)
- `host-nuc/rcrc` and `host-dalek/rcrc`, each with `HOSTNAME="<name>"`, that machine's `DOTFILES_DIRS`, and the existing EXCLUDES / COPY_ALWAYS. rcup links it to `~/.rcrc`.
- The loop (rcup needs rcrc to find the repo and host; rcrc lives in the repo's host folder) only exists on first install. Bootstrap once per machine (rcm reads the `RCRC` env var, `man rcrc`):
      RCRC=<clone>/host-<name>/rcrc rcup -B <name>
  After that, plain `rcup` reads `~/.rcrc` (= host-<name>/rcrc), which pins the same HOSTNAME and DOTFILES_DIRS: stable. Renaming the machine in the OS doesn't matter; renaming the host folder means running the bootstrap again.
- The human chose this over an unversioned per-machine ~/.rcrc.
